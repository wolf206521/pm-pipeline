# 需求追溯矩阵(RTM)· 机器可检总账

> 适用:中大型项目(多模块/多迭代)防四类失控——需求没落页面、页面没需求来源、同一对象状态多处定义、迭代后账目漂移。

## 核心思想

每条需求(用户故事 US)一行总账,打通五个维度:**需求 ID → 权威模块/PRD 锚点 → 原型页面 → 状态码 → 事件编码**。任何一个维度对不上,机器立刻报红,不靠人记。

## 文件格式(单文件,按模块分节)

```markdown
## M02 客服中心(源:10-模块/M02-客服中心/prd/v0.4.md)
| US | 标题 | 页面 | 状态码 | 事件 | 核销 |
|---|---|---|---|---|---|
| US-01 | 客服工作台 | M02-01 |  |  | 待核销 |
```

- **自动列**(US/标题/页面):由种子脚本从各模块最新 PRD 的用户故事节提取,重跑只刷新这三列
- **人工列**(状态码/事件/核销):构建过程中填写,种子脚本重跑时按键(模块+US)保留
- 页面列只留本模块锚点(Mxx-yy),跨模块引用不算锚点

## 种子脚本要点(scripts/seed_trace.py)

- 定位每个模块最新 PRD(版本号排序取最大),切片「用户故事」节
- 兼容多种 US 写法:`**US-01 标题**`、`- US-01(正常)Given...`、表格行 `| US-01 |`
- 保序去重;无标题的 US 标题列写「—」,不编造

## 四项机检(并入回归脚本)

1. **漏登**:最新 PRD 有 US 但 RTM 无行 → 报红(提示跑种子脚本补登)
2. **账目漂移**:RTM 登了但最新 PRD 已删该 US → 报红(确认是删除还是编号变更)
3. **状态越界**:RTM 填的状态码不在全局状态枚举文件内 → 报红
4. **页面悬空**:原型已存在时,RTM 页面锚点无对应 html 文件 → 报红;原型未建时跳过

## 纪律

- 新增/删除/改号 US → 先跑种子脚本,再跑回归
- 核销列在原型构建时逐条核销;核销标准 = 页面存在 + 状态码/事件已填 + 机检通过
- RTM 是唯一总账;任何「临时梳理的对应表」用完即弃或并入 RTM,不留第二份账
