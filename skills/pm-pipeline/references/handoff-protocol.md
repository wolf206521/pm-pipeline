# 无缝交接协议(handoff-protocol)· 多客户端/多账号/多会话续跑

> 场景:AI 客户端按账号有额度限制,工作会在任意时刻中断并换客户端/账号继续。原则:**会话不承载状态**——一切进度、决策、下一步都在文件里。

## 三层记忆

| 层 | 文件 | 内容 | 更新时机 |
|---|---|---|---|
| 断点现场 | `01-记忆/HANDOFF.md` | 当前阶段/进行中任务/下一步(可直接执行的命令或文件)/阻塞与待裁决/运行现场(服务、端口、未提交改动) | 每次会话结束前必写;长任务中途与额度预警时加写 |
| 工作记忆 | 模块 state.md | 模块级进度与待办 | 每轮模块工作结束 |
| 长期记忆 | 决策日志.md + MEMORY.md | 已裁决结论 | 每个确认点 |

## 开工仪式(接手固定顺序)

1. AGENTS.md(工程宪法) → 2. **HANDOFF.md(断点现场)** → 3. MEMORY.md → 4. 进行中模块 state.md → 5. WORKFLOW.md 继续

## 收工仪式(防断点)

1. HANDOFF.md 下一步写到「可直接执行」粒度(给命令/文件路径,禁「继续处理」)
2. state.md/决策日志同步
3. 提交并推送;推不了在 HANDOFF 标「未推送」
4. 重要产物做本地快照(版本库外内容)

## 切换策略

- 切换点选任务边界(子任务完成/闸门通过/测试全绿时最干净)
- 额度预警时主动收官当前任务:写交接单→提交推送→提示可切换
- 验收标准:新账号只说「继续」就能干活;达不到说明交接单不合格

## 防断层机检

- 开工自检:未提交改动/未推送标记 → 先处理
- 交接单质量自检:下一步必须含具体文件或命令

## 反例

- 状态留会话不写文件;交接单写「继续做」;只拿 git log 当记忆(没有为什么与下一步)
