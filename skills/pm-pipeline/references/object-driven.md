# 对象驱动原型法(object-driven)· 共享业务对象与多端视图

> 适用问题:产品是整体业务,不是模块拼盘。同一业务对象(订单/工单/报价/档案)会被多个模块、多个端(后台/客户门户/供应商门户)以不同视图消费——后台看全字段(含成本/毛利),门户看同一对象的裁剪视图(仅报价项与进度)。若每端各写一套页面,一致性只能靠人肉;本机制把一致性变成登记+机检。

## 三件套

### 1. 对象登记表 `object-registry.md`(原型根目录)

每个业务对象一节,机器可解析的固定格式:

```markdown
## OBJ-ORDER 订单对象
- 更新日期: 2026-10-14
- 状态机: 主链 S01–S30(权威枚举见 states 基线文件)
- 内部字段(客户视图禁出): cost_breakdown, margin, adjust_amount

### 字段视图矩阵
| 字段 key | 中文名 | 后台客服 | 后台主管 | 客户门户 |
| order_no | 订单编号 | ✓ | ✓ | ✓ |
| cost_breakdown | 成本明细 | ✗ | ✓ | ✗ |

### 消费页面
| 页面 | 视图 | 最近同步 |
| pages/M02/order-detail.html | backoffice | 2026-10-14 |
| (规划)门户-订单详情 | customer | — |
```

- **更新日期**是联动引信:对象的字段/状态/矩阵一变,日期 +1,机检自动列出全部「未同步」消费页
- **内部字段**清单是视图裁剪红线:客户视图页面出现即报错
- 消费页面表登记路径、视图、最近同步日期;规划中的端用 `(规划)` 前缀占位

### 2. 页面 manifest 消费声明

页面内嵌 manifest 增加顶层键:

```json
"objects": [ { "key": "OBJ-ORDER", "view": "backoffice" } ]
```

`view` 取值 `backoffice` / `customer` / `supplier` 等,与登记表视图列一致。

### 3. 机检(test_prototype.py ⑦)

| 检查 | 失败语义 |
|---|---|
| 页面声明的对象必须在登记表存在 | [对象未登记] |
| 声明消费的页面必须在登记表消费清单 | [消费未登记] |
| 登记表里的既有页面必须回声明 | [声明缺失](双向) |
| 页面声明视图 = 登记表视图 | [视图不符] |
| 消费页「最近同步」≥ 对象「更新日期」 | [未同步]——对象变了页面没跟上 |
| `view=customer` 页面不得出现内部字段 `data-field` | [视图泄漏]——成本/毛利等不得出后台 |

## 迭代工作流(变更传播)

1. 改对象(加字段/改状态/调矩阵)→ 登记表该对象「更新日期」改为当天
2. 跑机检⑦ → 自动列出全部 `[未同步]` 消费页(跨模块联动清单)
3. 逐页修改 → 回填「最近同步」→ 机检转绿才允许过闸门

## 与既有机制的关系

- 规则登记表(rules-registry)管**呈现规范**的回扫;对象登记表管**业务内容**的同步——同一套「登记+日期+机检」范式
- manifest 的 fields/states/ops 管**单页声明一致**;objects 管**跨页跨端一致**
- 视图矩阵的权限列与 PRD 的 ABAC/权限点定义对齐,客户视图禁出字段应与 PRD 权限节互查(人工/G 闸门)
