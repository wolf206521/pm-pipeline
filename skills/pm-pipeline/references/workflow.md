# WORKFLOW · 五阶段循环定义(通用模板)

每个模块独立走这条状态机。模块当前阶段记录在 `10-模块/<模块编号>-<模块名>/state.md`。

> 可选修订(多模块大项目推荐):原型体系 = **全局骨架先行 + 全部需求确认后统一出原型**——
> ① 先做 G0.5 全局原型骨架(IA+设计系统+导航壳),客户确认一次;
> ② 各模块循环只跑到 G3(需求+PRD+流程图确认);
> ③ 全部模块 G3 通过后,在 G0.5 骨架内统一产出全部原型页面(S4),统一 G4 确认。
> 原因:保证跨模块关联与同步,且不在需求未定前浪费原型工作量。

## 状态机

```
全局层(一次性,可选):
G0 状态与流程基线
G0.5 全局原型骨架:全系统 IA(菜单树/页面清单/共享页清单)+ 设计系统 + 导航壳原型 ── 客户确认 ──┐
                                                                                          │
模块循环(每模块,可并行推进):                                                              │
S1 需求采集 ──G1──> S2 PRD ──G2──> S3 流程图 ──G3──> [挂起等待]                            │
                                                        │                                 │
全局统一阶段(全部模块 G3 + G0.5 骨架确认后):              ▼                                 │
              S4 统一原型输出(所有页面在 G0.5 骨架内生成) ──G4──> S5 定稿交付+复盘 ◀────────┘
```

单模块小项目可省略全局层,S4 直接在模块内出原型。

## 各阶段定义

### S1 需求采集

- **先核对基线**:读 `01-记忆/源资料基线.md`,确认所用源文件是权威基线;源有更新就先跑 `scripts/refresh_baseline.py` 再动手
- 输入优先级:① 权威说明书的提取缓存 ② 设计大纲 ③ 客户口述/会议纪要 ④ 历史资料(仅追溯对照)
- 产出:`02-需求输入/<模块>.md` —— 需求摘要 + 源文件路径引用 + 待澄清问题清单
- 信息不足时一次只问 1–3 个高优先级问题(业务目标、核心用户、关键约束),其余按最合理假设写并标注

### G1 需求确认(确认点①)

- 产出:需求确认单(需求摘要 + 范围边界 + 明确不做什么),模板见 `templates/G1确认单.md`
- 出口条件:客户书面/口头确认,结论记入 `review/` 和 `决策日志.md`

### S2 PRD

- 工具:PRD 撰写 skill(如 laowang-prd),骨架模板见 `templates/`
- 产出:`prd/v0.<n>.md`(7 章骨架:背景指标 / 用户故事 / 状态机 / 字段字典 / 异常矩阵 / 埋点 / 范围外)
- 自检:`scripts/check_all.py` 中 `check_prd.py` + CHECKLIST 的 G2 闸门;配了 Jev 时追加 `scripts/check_semantic.py` 语义闸门(指标可量化/状态机有出口/字段字典完整,未配 Jev 自动降级为人工核对清单)

### G2 PRD 确认(确认点②)

- 出口条件:闸门全过 + 评审意见全部闭环(修改或记录为不采纳+理由)

### S3 流程图

- 工具:流程图 skill(如 laowang-diagram)
- 产出:`flows/*.mmd`(Mermaid 源码)+ `flows/*.md`(分层说明);需要拖拽精修时追加 `.drawio`
- 自检:`check_mermaid.py` + CHECKLIST 的「PRD ↔ 流程图」对照

### G3 流程图确认(确认点③)

- 出口条件:图中角色/主干/异常与 PRD 一致,客户确认流程讲法

### S4 原型输出

- 前置:(全局模式)G0.5 骨架已确认 + 全部模块 G3 通过
- 工具:HTML 原型 skill(如 baoyu-design)
- 产出:页面在骨架内生成(骨架含 IA/导航/设计系统,页面只填充模块内容);共享页面只建一份,各模块引用
- **页面完整性闸门**:IA 清单 100% 覆盖,缺页不放行——`scripts/test_prototype.py <原型目录> --ia <IA清单> --states <状态枚举>` 退出码必须为 0(页面完整性/链接有效性/占位残留/状态覆盖四项)
- **单页深度清单**:逐页对照 `references/prototype-depth.md`——字段 = PRD 字段字典逐项落位、交互可点、状态四态全覆盖(正常/空/错/加载)、权限态齐备
- 自检:CHECKLIST 的「PRD ↔ 流程图 ↔ 原型」三方对照 + 骨架一致性检查

### G4 原型确认(确认点④)

- 出口条件:三方对照无缺口 + 骨架一致 + 页面完整性闸门通过 + 单页深度逐页过 + 客户确认页面结构与交互

### S5 定稿交付

- `scripts/export_docx.py <模块>` 导出 docx 到 `20-交付/`
- 写 `30-复盘/<模块>-复盘.md`,进化结论按 `references/evolution.md` 落地
- `state.md` 阶段标记为 DONE
