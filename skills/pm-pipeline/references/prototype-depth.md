# PROTOTYPE-DEPTH · 单页深度规范(通用模板)

G4 闸门的「单页深度」判定标准。目标:任何一页拿出来,客户看到的是**能评审的页面**,不是示意草图。

判定分两层:**机器可查**的交给 `scripts/test_prototype.py`(本文件标注 🤖),**人眼看**的逐页对照本清单(标注 👁)。

## 页面结构五层

每个业务页面按五层自检。某层确实不适用(如纯展示页无操作),在页面标题旁标注「本页无 X 层:原因」,不允许静默省略。

### ① 导航层

- 👁 页面挂在 G0.5 骨架的导航里,当前位置有高亮/面包屑,能来回跳转
- 🤖 页面上每个内部链接/锚点可解析(test_prototype.py ②,死链不放行)

### ② 筛选层

- 👁 筛选项 = PRD 字段字典里标了「可筛选」的字段,一项不多一项不少
- 👁 每个筛选控件有默认值或「全部」态;时间类筛选写明粒度(日/周/月)
- 👁 筛选与列表联动:有「筛不出来」的空态(见下「异常与空态」)

### ③ 列表层

- 👁 列 = PRD 字段字典逐项落位:字段名、必填、默认值与字典一致;不出现字典里没有的字段
- 👁 状态列的取值 = 基线状态枚举,不发明状态名(🤖 test_prototype.py ④ 抽查状态覆盖)
- 👁 分页或「加载更多」有一个;单条记录的关键操作(查看/编辑)有入口

### ④ 详情层

- 👁 详情区(页内展开/抽屉/详情页)字段与列表层同源,补充列表放不下的字段
- 👁 只读/可编辑区分明确;可编辑字段标必填与校验提示,与 PRD 校验规则一致

### ⑤ 操作层

- 👁 每个按钮都能在 PRD 用户故事或流程图节点里找到出处;没有「摆着好看」的死按钮
- 👁 主操作可点,点击后有反馈(toast/跳转/状态变更示意);危险操作有二次确认示意
- 👁 权限态:不同角色看到的操作不同——至少做出「有权限/无权限」两种呈现,与 PRD 权限说明一致

## 状态四态(必备,缺一不放行)

每页必须做出四种呈现,可以用 tab、开关或独立示例页表达:

| 态 | 要求 |
|---|---|
| 正常 | 有贴近真实的示例数据(不编造业务数字;示例用占位风格但明确是示例) |
| 空 | 零数据时的空态:说明文字 + 引导动作(如「新建第一条」) |
| 错 | 加载失败/校验失败/权限不足的提示样式 |
| 加载 | 骨架屏或 loading 示意 |

## 异常与空态必备(与流程图对齐)

- 流程图每条异常分支 → 原型里有对应入口(错误提示、驳回态、重试按钮),或在对照表标注「不在原型范围」及原因
- 这两类信息必须回到 `review/一致性对照表.md`,G4 逐行核

## 呈现规范(客户评审反馈沉淀,与五层结构叠加适用)

五层结构管「有没有」,本节管「好不好看、读不读得懂」。九条通则:

1. **区块业务语义命名**:页面区块一律用业务语义名——基本信息/状态信息/明细信息/关联单据/进度时间轴/操作日志等;禁止「XX 头/XX 区/这一块」等口语名。区块命名清单以本规范为准;页面视觉标题与 manifest 的 `title` 一致
2. **字段呈现分层**:标签+冒号+值**紧邻成组**(标签值间距 ≤4px,标签次级灰、值主色加粗),字段组之间留白 ≥24px;栅格对齐指**字段组之间**的排列对齐,不是拉开标签与值(标签定宽把标签与值拉太远、不成整体,是反模式);关键值(金额/状态/编号)强化层级(大号/加粗/徽章)
3. **界面文案纯净**:出处/引用编号(如 US-xx、SM-x)一律不进界面,留在 manifest 的 `prd_ref`;界面只出现用户语言
4. **聚合卡片极简**:聚合/看板卡片只显示「分类 + 数量(或关键指标)」;内容摘要一律去详情页,卡片不下钻内容
5. **悬浮操作条**:页面级主操作(提交/分派/作废等)用 fixed 底部悬浮条,不随内容滚走;页面主体底部留白让位(≥ 悬浮条高 + 16px),内容不被遮挡;悬浮条避开左侧导航栏;危险操作在悬浮条上仍走二次确认
6. **状态展示整合**:当前状态 + 全程进度合并为一个进度区块(当前高亮 + 全程可见),不拆成多个块重复展示;界面零工程名词——状态机编号、权威归属、模块号等不进 UI,只留在 manifest
7. **成本要素结构化**:工艺/工序/材料类成本要素必须用结构化列表(行 = 要素,列 = 属性),禁止大段文字叙述
8. **进度展示组件统一**:同一语义(进度/阶段/状态流转)全站只用**同一个时间轴组件**(节点圆点+连线,完成/当前/未来三态);不允许同一产品里 chip、时间轴、步骤条混用
9. **文件预览页结构**:固定三段——预览区(带水印)+ 检查结果面板(逐项 通过/警告/失败 + 详情)+ 结论区(结论与状态分离,结论归结论、状态归状态)

> 落地纪律:规范新增后必须**回扫存量页面**——规范有了但页面没改 = 没落地(教训:先立规则后改页面,中间窗口期页面仍违规)。回扫结果记入当轮 `review/`。

## 页面声明约定(机器可查的前提:page-manifest + data-*)

五层清单里「字段落位/死按钮/危险操作确认/权限落位」原本是纯人工项。把声明写进页面,就能交给脚本(⑤)双向核对。约定:

- 每个业务页内嵌一个 `<script type="application/json" id="page-manifest">`,声明本页的:
  - `fields`: `[{"key","label","type","required","permission"?,"derived"?,"note"?}]` —— 派生展示列(PRD 字典外)必须 `"derived": true` 并写 `note` 说明来源
  - `states`: `[{"enum","label"}]`;`transitions`: `[{"from","to","op"}]`(op 必须能在 ops 里找到入口)
  - `ops`: `[{"id","label","prd_ref","confirm"?,"permission"?,"kind"?}]` —— `prd_ref` 指向 PRD 出处(用户故事/节点编号);纯 UI 演示控件标 `"kind": "ui"` 可豁免;危险操作标 `"confirm": true`
- 页面元素上打对应标记:
  - `data-field="字段key"` 标在渲染该字段的表头/单元格/表单项上
  - `data-state="状态enum"` 标在状态徽章上,元素文本 = manifest 声明的中文名
  - `data-op="操作id"` 标在按钮上;元素须带 onclick/href/data-feedback 之一(防死按钮)
  - `data-perm="权限点"` —— manifest 里声明了 permission 的字段/操作,页面须有对应标记
  - `data-confirm="true"` —— manifest 里 confirm:true 的危险操作,元素必须携带
- 四态(正常/空/错/加载)与权限 denied 态必须以静态 HTML 存在于页面(hidden 切换),不得只写在 JS 字符串里——否则静态扫描不可见,等于没做

脚本核对方向是**双向**的:manifest 声明了但页面没渲染 = 声明不落位;页面渲染了但 manifest 没声明 = 发明字段/状态/操作。给 `--prd` 时再叠加与 PRD 字段字典(名称/必填/类型)、状态枚举、操作出处的交叉核对。

## 与 test_prototype.py 的对应关系

| 规范条目 | 脚本检查 |
|---|---|
| 导航层链接可解析 | ② 链接有效性 |
| 清单页面 100% 存在 | ① 页面完整性(IA/nav 清单 vs 实际文件,缺页不放行;IA 可以是任何含 .html 引用的文本/JS 数据文件) |
| 无「待补/占位/lorem」残留 | ③ 占位残留检测 |
| 状态列取值 = 基线枚举 | ④ 状态覆盖(--states,抽查) |
| 字段/状态/操作 声明↔渲染双向一致、死按钮、危险操作二次确认、权限点落位 | ⑤ manifest 声明检查(页面内嵌 page-manifest 后启用) |
| 字段名称/必填/类型与 PRD 字典一致、状态枚举 ∈ PRD、操作有 PRD 出处 | ⑤ + --prd 交叉核对 |
| 四态呈现质量、筛选联动、呈现规范(区块命名/标签值分层/文案纯净/卡片极简/悬浮操作条/状态整合/成本要素结构化) | 人工逐页过(脚本不替代人眼) |

推荐调用:

```bash
python3 scripts/test_prototype.py 10-模块/<模块>/prototype \
  --ia 11-全局原型/IA.md --states 01-记忆/状态枚举.txt --prd 10-模块/<模块>/prd/v0.<n>.md
```

## 呈现规范·第二批(通用,源自真实评审循环)

> 第一批(区块命名/标签值/操作列/悬浮条/状态整合/编号展示/演示数据)见前文。以下为评审循环中沉淀的第二批通用规则,均建议落成机检。

### 版本化对象的呈现(报价/文件/合同等)

- 版本化对象详情页必须有版本历史(版本/关键值/状态/时间/操作=查看·对比);关联页须有历史入口
- 详情页头部当前版本 = 历史表「当前版本」行,两处不一致即 bug(可机检);跨页链接落地页的对象与版本须与来源引用一致
- 当前版本行视觉突出(统一样式如 `.row-cur`:浅色底+左侧色条);多对象列表页的版本列只显示版本号(v3),不标「(当前版本)」
- 版本切换必须真切换内容(标题/属性/结果/金额随版本更新),禁只弹提示的假切换——切换函数无 DOM 写入即可机检拦截

### 状态机与时间轴

- 一切进度展示统一横向时间轴(当前节点脉冲/完成/未来灰显);当前状态由卡片标题行徽章承载,卡片内不重复状态字段
- 互斥终态(如「已转单/已作废」二选一)不串行排主链,也不预设提示文字;默认只显示穿行节点,到达终态时主链末端追加对应节点
- 状态显示名映射:状态机权威名(逻辑口径)≠界面显示名(用户语言,如 已提交→待报价),映射表唯一来源;列表页只显示显示名不带状态码,详情页时间轴保留权威名+编码

### 表单与控件

- 字典字段(分类/工序/材料等)用选择器+级联,数据引统一演示数据集,禁纯文本输入;集合字段(明细行)必须多行增删;文件字段必须有空态+上传(点击/拖拽多选,真实读取文件名大小)+列表删除
- 字段集「1–N 项」即多选(推荐芯片样式:胶囊横排,选中变色+✓),禁单选下拉、禁裸复选框竖排
- 约束不进界面:字段标签只留字段名(+必填*),字符数/范围/条件只写 manifest/PRD;校验错误提示(操作后反馈)保留
- 全部 select 用全局统一样式(自定义箭头/边框/聚焦态),禁浏览器默认外观
- 操作列不空列:每行至少一个始终可见的只读操作(查看/详情);权限隐藏块不得包住全部操作

### 页面净化

- 页头=面包屑+标题(+必要操作),不展示功能说明/权限说明/数据声明等注释段(进 manifest)
- 演示环境标识不进页面:无「演示数据」徽标、无「(演示)」后缀文本;演示身份只由 manifest 与演示控制条表达
- 功能入口唯一:创建类入口(新建单据)可留页头;导航类入口(跳列表,与待办同效)去除,入口留在业务列表/待办区
- 逻辑性文字不进页面:门禁/权限/规则说明撤出(进 manifest);权限不足极简占位(无权限查看/无权限操作)

### 规则台账(rules-registry)模式

- 每条规则三合一登记:规则全文+检测方式+回扫记录(引入日期/最近回扫日期)
- 新规则入库必须回扫存量页面;「最近回扫日期 < 引入日期」即报未回扫(机器强制)
- 能机检的全部写进静态检查;同类问题第 2 次出现必须升级为机检项
